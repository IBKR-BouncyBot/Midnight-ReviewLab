# Midnight ReviewLab

Build the private expert-feedback marketplace for AI. Preserve real generated Compact execution and Midnight cryptography. Do not replace missing native artifacts with mock success or represent a local simulation as a zero-knowledge proof or accepted network transaction.

The source target is `https://github.com/IBKR-BouncyBot/Midnight-ReviewLab`. Its frontend target is ordinary GitHub Pages at `https://ibkr-bouncybot.github.io/Midnight-ReviewLab/`. Hosting the frontend does not host a prover, a shared database, or a Midnight node.

Use only the public owner alias `IBKR-BouncyBot` in notices, source attribution, Git metadata, logs and published artifacts. Do not publish personal names, email addresses, operating-system usernames or absolute personal filesystem paths.

## Evidence

- Keep Compact compiler 0.31.1 and compact-runtime 0.16.0 aligned with the supported integration. Review the full dependency graph before changing versions.
- Generate bindings and proof keys with the official compiler. Commit a real package-manager lockfile; never invent artifacts or test evidence.
- Run compilation, meaningful generated-runtime tests and a browser build after affected changes. Exercise the browser user journey before claiming it works.
- Report local contract execution, actual proof generation, accepted network transactions and website deployment separately.
- Keep private credentials, wallet seeds, sponsor keys, proof witnesses and private state out of source, browser exports, CI artifacts and public logs.

## Product boundaries

- Credential checks prove membership in an accepted issuer's registry. A self-issued demonstration credential is not professional accreditation.
- Bind each review to the campaign, credential secret and feedback commitment; prevent duplicate submission and reward claims.
- Keep campaign ownership, task deadlines, expertise requirements, credential expiry and capacity checks in the constrained contract where applicable.
- Review approval records and reward accounting are not actual transfers of money. Never display a completed payment without payment evidence.
- DUST is a nontransferable transaction-fee resource generated by registered NIGHT. A scenario estimate is not a live wallet balance, a price quote or a promise of unlimited transactions.
- Local AI evaluation tasks are sample content. Do not send prompts, answers or reviewer feedback to an external model without an explicitly implemented and disclosed integration.
- Treat imported files as untrusted. Validate their schema, bounds and commitments before use. Render user content as text.
- Private credentials stay in memory unless the user explicitly downloads them. Do not silently persist them in browser storage.

## Scope

Follow the user's GitHub Pages hosting request. Use test environments for proving and blockchain experiments; real-money settlement and production credential issuance need separately implemented infrastructure. Complete authorized work without an extra permission loop. Keep the application focused and publish only checks that actually ran.
